# FTPによる公開

nantenは静的サイトとして公開します。`pnpm build` で生成した **`dist/` の中身だけ**をFTPでアップロードすれば動作します。公開サーバーにNode.js・pnpm・PHP・データベースは不要です。

## 1. 手元でビルドする

Node.js 22.12以上とpnpmを使用します。

SNSのリンクプレビューを有効にする場合は、リポジトリ直下に `.env.local` を作成して公開URLを指定します。設定項目の見本は `.env.example` にあります。

```dotenv
SITE_URL=https://example.com/nanten/
```

ドメイン直下なら `https://example.com/` を指定します。URLにはHTMLファイル名ではなく公開ディレクトリを指定してください。末尾の `/` は省略しても自動で補います。HTTP・HTTPSの絶対URLだけを受け付け、認証情報・クエリ・フラグメントは指定できません。公開先を変えた場合はこの設定を変更して再ビルドします。

`.env.local` はGit管理対象外です。設定値はビルド時に読み込むため、サーバーへのアップロードは不要です。`SITE_URL` は公開情報であり、生成したHTMLにも含まれます。未設定または空欄でもゲームはビルドできますが、OGP・Twitterカード用メタタグとcanonicalは生成しません。仮の公開URLを自動で入れることはありません。

環境変数でも指定できます（次はPOSIXシェルの例です）。環境変数は `.env.local` より優先されます。

```sh
SITE_URL=https://example.com/nanten/ pnpm build
```

```sh
pnpm install
pnpm build
```

ビルドに成功すると次のファイルが生成されます。`assets/` のファイル名はビルドごとに変わることがあります。

```text
dist/
├── index.html
├── favicon.svg
├── ogp.png
├── icons/
│   ├── apple-touch-icon.png
│   ├── icon-192.png
│   └── icon-512.png
├── manifest.webmanifest
├── registerSW.js
├── sw.js
├── workbox-....js
└── assets/
    ├── index-....js
    └── index-....css
```

ビルドに失敗した場合はアップロードしないでください。開発用の `index.html` や `src/` をそのまま公開しても動作しません。

画面下部に `package.json` の `version` を `v0.2.0` のような形式で表示し、[GitHubリポジトリ](https://github.com/sakots/nanten)へのリンクを設けます。バージョンを変更した際も、再ビルドして公開すれば表示に反映されます。

## 2. FTPで配置する

FTPクライアントで契約サーバーの公開ディレクトリに接続します。接続先・認証情報・公開ディレクトリ名はホスティング会社の案内に従ってください。対応していれば暗号化されたFTPSまたはSFTPを利用してください。

- ドメイン直下で公開する例：`public_html/` に `dist/` の中身を配置 → `https://example.com/`
- サブディレクトリで公開する例：`public_html/nanten/` に `dist/` の中身を配置 → `https://example.com/nanten/`

いずれもアップロード先に `index.html`・`favicon.svg`・`assets/` が並ぶ状態にします。ディレクトリ構造とファイル名の大文字・小文字を維持してください。サブディレクトリのURLには末尾の `/` を付けます。`https://example.com/nanten/index.html` から開くこともできます。

`dist/` 自体をアップロードすると、公開URLにも `/dist/` が入ります。通常はフォルダーの中身だけを配置してください。

## 3. サーバーの条件

- `index.html` を既定のページとして表示できる一般的な静的Webサーバーを使用します。
- `.js` をJavaScript、`.css` をCSSとして配信できる必要があります。JavaScriptモジュールは正しいMIMEタイプで配信してください。
- PWAのインストールとService WorkerにはHTTPSが必要です（開発確認用の `localhost` は例外）。HTTPの公開サイトでは通常のWebゲームとしてのみ利用できます。
- `.webmanifest` を `application/manifest+json` または `application/json`、Service Workerの `.js` をJavaScriptとして配信してください。`sw.js`・`index.html`・`manifest.webmanifest` は再検証されるキャッシュ設定（例：`Cache-Control: no-cache`）を推奨します。
- Viteの `base: "./"` により、JS・CSS・favicon・PWA関連ファイルを相対パスで参照します。アプリ自体の配置先の変更に追加設定は不要ですが、SNS用の絶対URLを含む公開ビルドは `SITE_URL` を変更して作り直してください。
- アプリ内の画面切り替えはブラウザー内の状態で行い、履歴APIによるパス型ルーティングは使用しません。SPA用のリライトルールや `.htaccess` の追加は不要です。
- 外部の画像・フォント・API・CDNは不要です。牌はSVGで描画します。
- `file://` でHTMLを直接開く方法は対象外です。ブラウザーのモジュール制限があるため、HTTPまたはHTTPSで確認してください。

## 4. 公開後の確認

1. 公開URLを開き、ゲーム画面・牌・スタイルが表示されることを確認します。
2. 点数を入力して「答え合わせ」を押し、解説から次の問題へ進めることを確認します。
3. 出題範囲を変更し、ページを再読み込みしてもゲームが表示されることを確認します。
4. faviconが表示されることを確認します。

表示されない場合は、ブラウザーの開発者ツールでJS・CSS・faviconの404、MIMEタイプのエラー、アップロード漏れを確認します。HTMLとassetsは同じビルドのものを一式アップロードしてください。

## 5. 更新時の注意

- 更新のたびに `pnpm build` を実行し、新しい `dist/` の中身をアップロードします。
- 稼働中のページやService Workerから未アップロードのファイルを参照させないため、まず新しい `assets/`・`icons/`・画像・`workbox-....js`・`registerSW.js`・`manifest.webmanifest` を配置し、次に `index.html`、最後に `sw.js` をアップロードします。`dist/` の全ファイルが対象です。
- 古いハッシュ付きアセットは、更新前のページを開いている利用者が参照する場合があります。公開直後に一括削除せず、不要になったことを確認してから削除してください。
- 公開先に別のサイトがある場合、そのファイルやサーバー設定を削除・上書きしないでください。専用のサブディレクトリへの配置が安全です。
- ソースコード、`node_modules/`、`images/pai.png`、開発資料、設定ファイルはアップロード不要です。
- 成績はブラウザー内の練習中だけ保持します。サーバーへの保存やデータ移行はありません。

## 6. Twitterカード・OGPの共有画像

- 配信用画像：`public/ogp.png`（1200×630px、PNG）。Twitterの大きい画像カードとOGPで共用します。`pnpm build` で `dist/ogp.png` にコピーされます。
- 編集用原稿：`images/ogp.svg`。配色はゲーム画面と同じ深緑・生成りを基調とし、サービス名・麻雀牌・「その手、何点？」を配置します。スクリーンショットや他サービスの素材は使用しません。
- 公開時は `ogp.png` もFTPでアップロードしてください。SVG原稿はアップロード不要です。
- `SITE_URL` を設定してビルドすると、`og:url`・canonicalに公開URL、`og:image`・`twitter:image` にその直下の `ogp.png` の絶対URLを埋め込みます。たとえば `https://example.com/nanten/` なら画像URLは `https://example.com/nanten/ogp.png` です。
- OGPのタイトル・説明・サイト名・言語・画像のサイズと代替文、Twitterの `summary_large_image` カード用メタタグも生成します。JavaScriptを実行しないSNSクローラーでも、生成済みHTMLから読み取れます。
- 画像は認証なしで公開アクセスできる必要があります。設定を変更しても既存のSNSプレビューはキャッシュされる場合があります。SNS側での実際の表示確認は、FTP公開後に行ってください。

## 7. スマートフォンのPWA

### インストールと起動

- Android：HTTPSの公開URLをChromeで開き、メニューの「アプリをインストール」または「ホーム画面に追加」を選びます。表示名はブラウザー・OSにより異なります。
- iPhone／iPad：SafariでHTTPSの公開URLを開き、共有メニューの「ホーム画面に追加」を選びます。「Webアプリとして開く」が表示される場合は有効にします。
- ホーム画面の「nanten」アイコンから開くと、ブラウザーのアドレスバーを表示しない独立した画面で起動します。OSのインストール画面をアプリから強制表示することはしません。
- アイコンは192×192・512×512のPNGと、Apple用180×180のPNGを用意します。共通原稿は `images/app-icon.svg` です。マスク可能なアイコンの安全領域内に牌を配置します。
- マニフェストの開始URLとスコープは `./` とし、ドメイン直下とサブディレクトリのどちらでも配置先のゲームを起動します。`SITE_URL` の指定はPWAには不要です。

### オフラインと更新

- 本番ビルドでService Workerを登録し、ゲームのHTML・JS・CSS・牌描画に必要なファイルとアイコンを事前キャッシュします。開発サーバー（`pnpm dev`）では登録しません。
- 初回はオンラインで開き、キャッシュの準備が完了する必要があります。その後は圏外・機内モードでも起動して10問の練習ができます。OSやブラウザーがサイトデータを削除した場合は、オンラインでの再読み込みが必要です。
- 新版を検出するとバックグラウンドで取得し、旧版で開いている画面をすべて閉じた後に切り替えます。練習中の強制リロードは行いません。更新時はホーム画面のアプリとブラウザーの同サイトのタブをすべて閉じ、再度開いてください。
- 成績・回答の永続化は行いません。アプリを閉じたり再読み込みしたりすると練習は初期状態に戻ります。オフライン対応は進行状況の保存機能ではありません。
- キャッシュ対象は配置ディレクトリ内のゲーム用ファイルに限ります。SNS共有画像や外部サイトへのリンクはオフライン利用の対象外です。

### 動作確認

1. `pnpm build` → `pnpm preview` で本番ビルドを開きます。LAN内のHTTPアドレスではなく、同一端末の `localhost` またはHTTPSで確認します。
2. 開発者ツールでマニフェスト・PNGアイコン・Service Workerが読み込まれ、Service Workerが有効になっていることを確認します。
3. オフラインに切り替えて再読み込みし、問題表示・回答・次の問題への移動ができることを確認します。
4. 実機でホーム画面への追加とアイコンからの独立画面起動を確認します。更新後はすべての旧画面を閉じ、新版に切り替わることを確認します。
